# Shared authentication request budgets — local prototype

This change is not deployed and its forward-only migration is not applied to Render. Login flags are unchanged. Disabled web session reads and native availability retain existing signed-out/unavailable responses without a budget query. No provider or customer data is sent by this work.

Enabled issuance/read operations consume a global per-operation PostgreSQL allowance before session/provider work. Demo defaults needing operations review before real traffic:60/minute for web start/callback and native handoffs/authorize POST/callback/exchange;120 for native authorize GET;300 for each session/availability operation. No IP/header, user ID, secret or arbitrary configuration context becomes a key. A single attacker can exhaust a global allowance. This is not per-client fairness or verified edge abuse protection; native edge-verification requirements remain unchanged.

Web logout, native logout and native cancellation are EXEMPT from the new time budgets. Their existing independent per-process concurrency limits, parsing, origin/ownership checks, durable revocation and database timeouts remain. This avoids adding a new attacker-exhaustible minute-long recovery block. It does not guarantee recovery availability during underlying database/pool/service overload. The inert native failure page is also exempt.

A window lasts60seconds from its first admitted request. PostgreSQL clock_timestamp() is read AFTER acquiring the operation row lock. At start+60000ms the window resets; counters saturate at limit+1. Ten preseeded rows have fixed cardinality and need no cleanup. A backward database clock relative to persisted window start fails503 until time catches up or operator review. Forward wall-clock jumps may reset a window; this is not monotonic protection against arbitrary database clock manipulation.

Missing migration/row, connection/lock/query failure or invalid stored state fails503. Global exhaustion returns429 with Retry-After1..60, no-store/no-referrer and no cookie clearing. Exception: enabled browser callbacks sanitize all budget/outer-concurrency failures to their existing fixed303failure URL, preserving Retry-After when present and never echoing provider code/state. Disabled/incomplete callbacks also redirect303, using fixed relative destinations without trusted configuration or request-host interpolation. A429/503 is not proof of signed-out state or successful revocation; clients hold private UI until verified recovery.

One additional budget pool connection per app process is separate from existing auth-store pools. Connect/query/statement timeouts are1500ms each, idle timeout10seconds; these are not one end-to-end deadline. Existing per-process concurrency admission remains. Native busy/retained-record quota429 responses retain existing behavior; web local concurrency failures remain503 except callback sanitization.

The explicit docs/customer-auth-request-budget-migration.sql creates a new schema only. Apply separately as migration owner after approval. It deliberately fails if already present, granting runtime only USAGE and SELECT/UPDATE; no INSERT, DELETE, DDL or future default grants. No existing auth schema is altered; no automatic migration, cron or environment setting is introduced. Deployment without migration makes enabled issuance/read operations fail closed; disabled apps remain usable and recovery retains existing storage behavior.

Thresholds live in AUTH_BUDGET_LIMITS. Changes need traffic/operations review and schema compatibility; reducing a limit below a retained counter can fail503 until deliberate reconciliation. Never reset live budgets casually. Shared limits span all app instances/configurations using this dedicated database.

Tests separately cover database atomic admission through independent pools in one Node process (not literal multi-process clients), boundary arithmetic, clock regression, missing schema, lock timeouts, controller callback redaction, disabled bypass, exempt recovery and client429 continuity. Local evidence does not establish hosted enforcement or provider eligibility.
