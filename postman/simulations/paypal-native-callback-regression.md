# Fictional native PayPal callback simulation

Run `python3 tests/paypal-native-callback-simulation.py` from the repository. The runner snapshots the relevant local source and fixture, checks resource limits, and starts a Postman simulation in private network and mount namespaces. It masks the local Postman state and supplies fictional credentials only. Its output directory is reported at startup.

The actual native and web controllers and OpenID adapter use fictional in-memory stores and a loopback provider. The fixture creates its own temporary RSA signing key. The driver checks the fictional Basic and Bearer headers before mapping requests into Postman and replaces them with fixture-only signals; those headers are not tested across a real network or logged by the mock. The mock is local-only and should not be deployed.

The run exercises successful signed native callbacks with and without informational scope and with ignored extensions, plus duplicate scope, an unsupported hybrid token, control-bearing scope, mismatched issuer and missing required issuer. It also checks a successful web callback, an unsupported web token field, a mismatched web issuer, rejection of an unavailable earlier transaction, failure to issue a session after a valid provider exchange, and a delayed response followed by a successful newer attempt. Invalid provider responses do not cause a token exchange; the simulated session-issuance failure occurs after one. Its in-memory web store models claim-time replacement of the transaction values with non-secret markers, and the failure scenario checks those markers. Its in-memory native store models clearing provider values on reservation; issuer failures assert those values are absent from that model. Fixed return links do not contain provider scope, issuer or extensions. It does not test PostgreSQL, a real PayPal provider, TLS, user consent, device behavior or a deployed release. The companion context file records source evidence and unresolved provider assumptions.
